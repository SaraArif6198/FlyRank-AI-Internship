03 · Pressure test

The chosen road gets the hardest questions.

The front-runner must survive actual delivery and display needs, not just sound familiar.

What breaks with the simplest?

Not launch. Change.

Plain HTML can ship everything essential. The drag appears when seven repeated cases and gallery behavior must stay consistent through edits.

What do I maintain?

The adapter counts.

Components, case data, Tailwind classes, dependencies, Git, and Vite/vinext/Nitro. The earlier Vercel 404 is the honest maintenance evidence.

Can I finish in two weeks?

Yes—with cuts held.

Identity, case copy, images, map, and CTA ladder already exist. No redesign, CMS, account system, or custom backend enters build week.

Does it show the work well?

Yes, without spectacle.

Responsive galleries, readable expanded cases, explicit demo/repo links, and restrained motion support the proof instead of upstaging it.

04 · My decision

React wins—with a maintenance contract.

This is Sara’s rationale after the comparison and pressure test.

I chose Vite + React + Tailwind CSS + Framer Motion, hosted on Vercel. Plain HTML would work, but I would maintain repeated project markup as the portfolio grows. Astro is a sensible content road, but migrating now spends the build window on a new framework instead of showing the work.
Can I maintain this?

Yes. React, Git, component state, and deployment configuration are within my current skill set. Every dependency change still owes me lint, a production build, and a public URL check.

Does it show my work well?

Yes. Real screenshots, long-form proof, demo/repository links, and the scope builder get one repeatable structure.

Backend?

Not yet. Local content plus a browser-built email covers launch. Server code arrives only with a real storage, privacy, or processing need.
